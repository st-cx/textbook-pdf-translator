# 大书质量修复的复盘与完成标准

Rosen 的多轮迭代暴露了一个事实：译文存入数据库、PDF 能生成和教材能可靠阅读，是三个不同结果。此前过多工作停留在局部修复和技术检查，没有及时把真实成品中的缺译、整页英文和图形缺失作为首要指标。这是实现和验证策略的问题，不能全部归因于模型或书太复杂。

## 为什么迭代没有及时收敛

| 根因 | 用户看到的结果 | 本轮处理 |
|---|---|---|
| 原书图形先被拆散，后面再猜关系 | 孤立点遗漏、小树竖散、照片重复 | 在有明确图注、分隔线和原生绘制证据时保留完整图形单元；无法确定的范围保留诊断 |
| 小包失败中止整个任务 | 重跑多次，后面正常段落仍没有请求 | 无进展只停止当前小包，后续小包继续；失败记录、部分保存和总请求上限保留 |
| 来源框、字体名义框、实际墨迹与中文测量混用 | 一个标签使整页中文回退英文 | 分别核对原墨迹、可用空间和实际中文测量；不缩字，不靠扩大背景掩盖未知内容 |
| 错误只剩泛泛的“解析待修复” | 不知道哪些页能翻、为何失败 | 排版错误保存稳定原因码与关联内容编号，私密路径和原始异常不进公开提示 |
| 保存数代替显示数，出稿代替完成 | 程序显示结束，读者仍遇到大量英文 | 窗口明确显示实际中文、未译、整页原文和局部英文；有缺口时显示待处理 |
| 修复范围持续扩大、长任务每次重跑 | 时间增长，旧问题和新发现混在一起 | 冻结源、译文和排版器；有限补译；先回放固定失败页，再做一次全书重排 |

## 本轮固定范围

1. 从 rc.7 的真实成品建立基线：37个整页原文保留页、2,310个未译或未采用元素，以及已确认的树图/重复照片问题。
2. 缺译按来源阻断、尚未请求、校验拒绝、过期版本等互斥原因登记。只对符合现有安全规则的138个任务、679个缺项做一次有限调度；不把所有失败清空后循环重试。
3. 修复可用自创材料重现的共同根因；真实残词、缺失下标和未知图文归属仍明确列出，不通过放宽公式或数字校验清零。
4. 停止请求后再登记来源变更。未变内容的来源与规则哈希核对一致，旧译文记录保留，不复制旧语义通过。
5. 对冻结输入生成独立新稿，核对实际PDF及风险页，再打包发布。原工具、旧窗口和旧稿不自动覆盖。

## 怎样才算本轮交付完成

- 新增行为回归与全套本地测试通过，源码与测试回执相符。
- 有实际PDF读回数据：原页覆盖、输出页数、显示中文、未译、整页原文和局部英文分别统计。
- 已修的关键图形在最终PDF中再次查看；未通过项保留可定位清单。
- 有不含教材、译文、密钥及私人任务的源码包，另有保留配置与任务的本机升级包；远端发布内容读回一致。

这定义的是一次可交付的改进，并不等于全书最终验收。最终验收仍要求未解释内容缺失、数学结构错误和严重版面问题得到解决；局部样本、通过数增加或测试通过均不能替代它。最新实测结果见[全书进度](ROSEN_PROGRESS.md)。

## 剩余问题怎样推进

当前冻结输入仍有1,692个未译或未采用项，其中1,250个受到当前来源结构门禁阻断，另442个需要继续调度或核对候选。后者是既有逐项证据与本轮请求结果的对齐，不是重新领取任务后的状态；其中274个在本轮限定调度范围外，下一次仍需核验资格。这是实施时主动限制批次以便冻结交付，并非缺少用户的全书授权。原文保留页和局部英文标签属于最终显示缺口，另行统计。

1. **完整内容单元与阅读关系优先。** 集中处理18条裁片隔离/角色诊断及33条阅读流诊断；点、线、标签、图像和题干必须有唯一归属，不能以隐藏碎片消除提醒。第330页求和碎散、第1055页图中数字脱离是保留的真实失败例。
2. **按机制修复墨迹与公式结构。** 740条墨迹诊断和957条数学结构诊断分别建固定故障集，按字体/gid/完整矩阵、完整运算式与上下限关系批量验证。诊断数不是已确认错公式数量；影响的缺项有交叠，不能相加当成修复收益。
3. **再恢复可翻译范围。** 442项按未执行、无候选、数字等价、角色和语义拒绝分类处理；先核当前身份，再调用模型。模型不能替代原文结构修复，也不能把代码强改为中文。

每个共同根因先通过“原失败单元、阴性例、连续区域、固定严重风险页”四层检查，再冻结输入重排全书。只改变局部时，缓存必须包含来源、保护对象、邻近上下文与样式依赖；全局规则变化仍需最终整书出稿。之后用实际PDF的显示缺口和视觉结果判断改善，避免再次以版本号、测试数量或累计译文数作为完成标准。[当前分类汇总](../evidence/rosen-convergence-20261030.json)

## 速度怎样衡量

翻译确实使用并行执行器，默认32、可手动调整1–32。每条路线仍有自己的并发、限流和冷却；同任务内的小包按顺序保存，因此批次尾部可能只有少量长任务在跑。多个路由名称不等于等量独立容量，配置的RPM也不等于实际吞吐。

分别记录批次实际耗时、请求数、明确的HTTP限流、其它失败和用量缺失。累计并发请求耗时不能直接当作总耗时；未知价格不记为免费。后续性能优化应在相同固定样本上比较，不能只调大并发数字或以删除校验换取速度。

本轮第一个全书候选记录约89分钟，但Windows电源事件与文件时间共同证明其中约70分钟处于系统待机。合并保存只比rc.7多约10秒，分割失败次数反而减少。这个候选随后因新增标签回退被保留为历史证据，不是交付稿。不能将待机归咎于排版算法，也不能把扣除待机后的数字当作同输入性能评测；最终稿耗时另行记录。
