# 自己运行：自动翻译与中文阅读稿

双击项目目录里的 **开始翻译.bat**。已安装版直接打开；首次下载的源码请先按[安装说明](INSTALL.md)安装依赖并填写自己的 `config.json`。

1. 选择原 PDF 和任务目录。页码留空处理整本；试用可填 `1-10`，它表示 PDF 物理页。
2. 选择翻译、复核模型。**翻译并发默认32，可手动输入1–32；每批任务数随并发设置变化。** 限流或连接不稳定时可降到4、8或16。推荐先用“快速抽查”。
3. 点击“开始 / 继续翻译”。已保存且原文、公式、规则版本匹配的译文直接复用。
4. 结束后点“打开任务目录”，进入 `reading_draft`，打开 `*_中文阅读稿.pdf` 和 `阅读稿检查清单.html`。

继续时选择**相同任务目录**，不用重新选择原 PDF。不要改动其中的 `book.json`、`tasks.db`、`assets` 和 `coverage`。原 PDF 需要留在原位置。换书或换分析页码请新建任务目录。

大任务启动时要读取和核对已有书籍结构。当前Rosen记录约494MB，本机真实续跑检查耗时约135秒，期间没有API调用，窗口后台工作；这段时间请勿重复启动。这个耗时是启动检查，不是全书翻译速度。[实际检查摘要](../evidence/automatic-handoff-20261024.json)

## 停止、看稿和恢复

“安全停止”会等待当前一批提交保存，不再开始下一批。正在等待模型时可能需要几分钟；生成阅读稿时会在当前分段排好后停止。关闭运行中的窗口也会先请求安全停止。不要同时用多个窗口运行同一任务。

想先看进度，停止后点“只生成阅读稿”。这个按钮只使用已有译文，不调用翻译或复核 API；已排好的分段在输入和文件都未变化时直接复用。

运行中设置会冻结；要调整并发或模型，先“安全停止”，修改后再开始，已有效的译文继续复用。停止生效需等当前批次保存。

连接失败、余额不足、模型返回格式错误或个别任务反复失败，会保存有效结果并结束或跳过该范围。恢复连接或修复对应问题后，再打开同一目录继续。程序不会自动清空历史失败、旧译文或语义复核记录。

翻译模型可选已配置的**多路由供应商池**，也可手选单个供应商。池内各路线并行分担任务；某条限流时冷却并尝试其他路线，某条额度或权限不可用时在本轮停用该路线。全部不可用时保留进度结束，恢复后继续。复核模型单独选择。池内健康状态与限速时钟跨批复用；同一配额的别名共享限速和容量。[路由配置](MODEL_ROUTING.md)

## 阅读稿怎样处理疑难内容

自动模式把常规翻译和最终验收分开，不因一处解析风险停止整本付费工作。

- 公式占位符身份、数字及提交版本仍然检查；来源错误范围及依赖上下文不发送给模型猜测。
- 同题超过6个元素也能翻译：每次请求最多6个完整元素，附上完整原题组作为只读上下文。已保存的元素不重复请求，独立论证复核仍走原联合流程。
- 某个小包反复返回无效结果时，保留拒绝原因并停止这个小包，继续同任务后面的完整小包；不会清除失败，也不会无限重复请求。暂停、取消和每任务请求上限继续生效。
- 未译块使用原文并明确标记。模型语义复核不通过的文字不会冒充已通过译文。
- 一段重排失败会自动缩小范围；跨页公式、题目和明确图文关联不会被重试过程拆开。仍无法排好的范围逐页保留完整原页和“尚未译成中文”提示。
- 图内未译标签暂时保留原PDF字形与颜色，避免窄英文框塞入中文字体后让整页退回英文；其余中文继续显示。原生标签及其中的公式单列记录，仍需检查。
- 已译标签在安全宽度内仍实测超出原图空间时，阅读预览只对该标签保留原生英文。其译文继续保存，但不计入稿件实际显示中文；正式严格排版仍要求修复。
- 阅读稿保留全部选中原页的去向，并提供“原书页码 / 原 PDF 物理页 → 阅读稿页”的清单。
- 正文、习题、图注使用固定角色字号，不缩字塞入原框。改版式可以只重排，不必重新翻译。

阅读稿始终标作待检查，不等于正式验收通过。报告分别统计数据库已保存译文、稿件实际显示译文、未译块、保留原页和来源诊断，逐页给出实际显示与需译数量。正文提示仅描述当前页面，具体诊断留在清单中。复杂公式整体边界、图文关联及最终视觉效果仍需成品检查；严格阶段命令继续保留。

窗口结束提示会直接列出实际显示中文、未译或未采用、整页原文、已存但仍显示英文的标签，以及来源待处理数量。只要仍有这些缺口，就显示待处理状态；安全停止或预算用完的状态不会被出稿覆盖。新分析可识别有明确原生证据的完整图形单元；旧任务不会因升级自动重新分析或重置译文。

## 抽查与速度

“快速抽查”每次最多复核32个已完成元素；“较严抽查”最多128个，均不是全书每句复核。“先翻译”不调用独立语义复核。来源、公式标记、数字和事务提交检查始终存在。完整数学论证、跨页语义单元不会被拆成普通抽查而宣布通过。

旧流程慢，主要因为翻译中穿插了逐项来源修复、重复全书检查和大量人工目视；模型本身也可能把时间花在思考、限流等待和重试上。自动模式启动时读取一次书籍状态，分批复用现有任务，常规翻译不逐段等待第二个模型，抽查在翻译后进行。最终全量像素、语义和人工检查可等阅读稿出来后单独做。

并发数是同时处理任务的上限；实际在途请求还受剩余任务、每条路线容量、每分钟请求限额及冷却时间约束。32并发不保证恒定32个请求同时在途。日志显示本批任务数与并发上限，每批结果都会保存。

实际速度取决于模型、网关、并发和书籍结构。小样耗时不能保证全书耗时；程序会显示本次已保存数量、速度及请求用量。网关未提供可靠价格时，估算零值不表示免费。不要为了消耗额度重复翻译已有效的内容。

## 命令行自动模式

```powershell
# 自动处理并生成阅读稿，可重复运行续传
.\.venv\Scripts\python.exe translate_pdf.py "书.pdf" --auto --out "书的翻译任务" --provider translation-pool --workers 32

# 手动改为16并发，默认每批16；已有有效译文继续复用
.\.venv\Scripts\python.exe translate_pdf.py --auto --out "书的翻译任务" --provider translation-pool --workers 16

# 有限试跑 + 翻译后独立抽查
.\.venv\Scripts\python.exe translate_pdf.py --auto --out "书的翻译任务" --provider example --review-provider review --max-tasks 8 --review-limit 32

# 无API调用，仅生成/刷新已有任务的阅读稿
.\.venv\Scripts\python.exe translate_pdf.py --auto --out "书的翻译任务" --draft-only
```

自动模式的运行摘要为 `autopilot_status.json`，进度日志为 `autopilot_events.jsonl`；唯一翻译状态仍由原来的 SQLite 任务库持有。不要把状态摘要当作另一份译文缓存。

自动模式省略 `--workers` 时默认32；显式 `--batch-size N` 可单独限制每批数，未指定则跟随并发。原有分阶段命令默认4并发，仍可使用 `--workers` 调整。

## 把成品交回检查

保留整个任务目录。交付检查时使用阅读稿 PDF、`reading_draft_report.json`、`阅读稿检查清单.html`、`autopilot_status.json`；需要定位重排或重译时再使用本地书籍结构与任务库。公开反馈请只发可合法共享的最小示例，勿上传私有教材、密钥或数据库。
