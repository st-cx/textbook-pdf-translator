- PDFMathTranslate-next v2.9.0, commit `0fe22805a7cb60eadf6a864315b3b91a9ddd2f64`: https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/tree/v2.9.0 — AGPL-3.0. Reference for OpenAI-compatible adapters, glossary, rate limiting and cache impact parameters. This package's translation worker and state machine are independently implemented and do not vendor its code or install the conflicting full application.

The original local translation engine is retained as `legacy_translate_pdf.py` for compatibility. Windows fonts are resolved from the local operating system and are not redistributed in the upgrade package.

Four self-authored geometric test fonts and their generators are included: `tests/fixtures/original-zero-advance.ttf` (1,324 bytes), `original-tall-containers.ttf` (944 bytes), `original-ordinary-ink.ttf` (1,252 bytes), and `original-ordinary-ink-distinct.ttf` (1,256 bytes). They reproduce zero-advance math marks, tall mathematical containers, and ordinary glyphs with overhanging ink or distinct same-name font programs. None is a system, textbook, or production Chinese font. The fixtures and generators use this repository's license.

Regenerating these fixtures optionally uses fontTools 4.60.2 (MIT); normal installation and tests do not install fontTools or depend on it at runtime.

Dependency versions used during acceptance are recorded separately in requirements-lock.txt. Upstream model/font assets, when needed by BabelDOC, are cached inside each configured task/cache directory; their own upstream licenses remain applicable.

Local neural structure hints additionally use the official DocLayout-YOLO DocStructBench ONNX artifact selected by BabelDOC 0.6.4. SHA3-256: `60be061226930524958b5465c8c04af3d7c03bcb0beb66454f5da9f792e3cf2a`; 75,324,598 bytes. Source: https://huggingface.co/wybxc/DocLayout-YOLO-DocStructBench-onnx . The public source repository contains model provisioning code, not these model weights. The local adapter keeps native source glyphs, original mathematical vectors and exercise boundaries authoritative.

The local wrapper consumes explicit ONNX files using CPU ONNX Runtime; it does not install or call PyTorch, Pix2Text, Ultralytics cloud inference or a document upload service.
- The three default ONNX models below are the exact artifacts bundled in the RapidOCR 3.10.0 wheel. Their upstream weights belong to Baidu and/or the applicable PaddleOCR rights holders, separate from RapidOCR's source/engineering authorship. The wheel's `MODEL_LICENSES.md` identifies these weights and converted representations as Apache-2.0 and retains upstream attribution: https://github.com/PaddlePaddle/PaddleOCR . Bootstrap copies both `LICENSE` and `MODEL_LICENSES.md` beside the model copies. Model filenames alone are not identities; each size and SHA-256 is checked against `ocr_engine.MODEL_SPECS`.

- The MFD inference wrapper is independently implemented with the existing ONNX Runtime/NumPy/OpenCV dependencies. It reads the exported model schema and performs local RGB letterboxing, class-score decoding and duplicate-anchor suppression; no CnSTD/Ultralytics/Pix2Text source is vendored. Upstream usage reference: https://github.com/breezedeus/CnSTD/blob/master/cnstd/yolo_detector.py ; model documentation: https://pix2text.readthedocs.io/zh-cn/stable/models/ .

`python -m textbook_pdf.bootstrap` is the explicit provisioning operation. It retains the existing pinned DocLayout setup, copies verified OCR models into the tool's `.cache/scan/ocr`, and downloads MFD only from the fixed revision above into `.cache/scan/pix2text-mfd-1.5.onnx` when a valid file is absent. `TEXTBOOK_OCR_MODELS` and `TEXTBOOK_MFD_MODEL` can override the local destinations. Download/copy data is validated in a unique same-directory temporary file before atomic replacement. Failed preparation preserves existing files. Ordinary analysis, OCR and formula/layout inference never invoke this downloader or send book pages. Inference confidence and unchanged-geometry pixel checks do not certify OCR completeness or mathematical meaning.
